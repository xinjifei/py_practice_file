# 第 66 天验收标准

## 体系定位
- 所处阶段：阶段四「AI 核心技术」——从阶段三的「产品思维 / 工作流」跨入 AI 底层原理的第一课
- 角色：Token 是整个「LLM 工作原理」section 的地基（section 第 1/4 天）。不理解 token，后面的 Embedding、Context Window 参数都悬空
- 目标关系：技术判断力。理解 LLM 底层机制，才能在用 AI 时判断「为什么这样输出」「为什么有长度限制」「为什么按 token 计费」

## 分层深度

| 层次 | 时间 | 目标 | 到此为止 |
|------|------|------|----------|
| 极简 | ~15min | 亲眼看到中文被切成 token，确认 token ≠ 字；建立 Context Window 上限的直觉 | 不碰 tiktoken 的 API 细节 |
| 正常 | ~30min | 跑通统计：token 数 vs 字数比例、中英差异、不同 tokenizer 差异；能说清自回归「一次一个 token」 | 不扩展到 BPE 内部算法 |
| 充裕 | ~45min+ | 深挖：BPE 为什么常见词 1 个 token、生僻字拆开；token 与计费/成本的关系；中文 token 效率为什么低于英文 | 可深挖方向：tokenizer 训练原理 |

## AI 分界线
- **归你（必须长在脑子里）**：Token 是模型的最小语义单位（不是字不是词）；自回归生成（每次只输出一个 token）；Context Window 上限的成因——这三条是判断力
- **可外包（概念要知道、实现交给 AI）**：tiktoken 的具体 API（get_encoding / cl100k_base / o200k_base 这些名字）、BPE 分词算法的内部实现

## 硬线（不过不能结束）
- [ ] 能用自己的话解释「Token 是什么」，并能说明为什么一个中文词可能被切成多个 token（不要求背 BPE 细节，但要能说清「模型看的是片段不是字」）
- [ ] 能解释「为什么模型一个字一个字往外蹦（自回归），为什么不能一次输出整篇」
- [ ] 能解释「Context Window 为什么有上限，为什么对话越长越慢越贵」——这是第 68 天 Context Window 参数的地基

## 软线（可选）
- [ ] 能说出不同 tokenizer（cl100k_base vs o200k_base）对同一文本的 token 数不同（知道存在即可）
- [ ] 了解 BPE 分词的基本思路（常见词 1 个 token、生僻字拆开）（可深挖，后续不硬依赖）
