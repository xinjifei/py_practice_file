# 第 69 天验收标准

## 体系定位
- 所处阶段：阶段四「AI 核心技术」› LLM 工作原理（概念层面，零PyTorch），第 4/4 天 —— **本 section 收尾**。
- 前面铺了什么：d66 Token（模型怎么"读"文字）、d67 Embedding（怎么"懂"语义）、d68 Context Window / Temperature / Top-P（怎么"被控制"）——三天都在讲**模型是什么**。
- 今天的概念：**怎么用语言去指挥模型**。System Prompt 是"设定舞台"，User Prompt 是"指定任务"。
- 和目标的关系：这是从"理解模型"跨到"操作模型"的转折点，下一个 section（d70-73 Prompt Engineering 在量化场景中的应用）整段建立在今天之上。归到能力拼图里是 **AI 协作能力的第一块砖**——高效指挥 AI 的入口不是会写代码，是会定义角色和边界。

## AI 分界线
- **归你（必须长在脑子里）**：
  - System / User 的分工逻辑——为什么这个划分存在，同一句 User Prompt 在不同 System 下产出为什么不同
  - 四要素（角色 / 能力 / 边界 / 输出格式）各解决什么问题
  - 判断力落点：拿到一个 System Prompt，能看出它缺哪个要素、缺了会出什么问题
  - 成本意识：System Prompt 是每轮都重复发送的文字，它有 token 代价
- **可外包（概念要知道、实现交给 AI）**：
  - 具体措辞怎么写更漂亮、有没有更好的表达——AI 润色比你快
  - 现成的 System Prompt 模板（GitHub 上一堆）
  - 具体 API 调用代码（messages 结构、role 取值）
