# ollama大模型本地部署
> 本地运行大模型

## 基础概念
- 之前在学习过程中不管是练习脚本，还是使用的智能体，全部是使用的线上API调用的大模型。
- 但是在一些情况下需要在本地运行大模型，因为在本地大模型有这样的优势
1. “免费”运行，不需要支付API费用（不包括设备）
2. 隐私性，不需要发送任何东西出机器
3. 稳定性，不受网络影响，全本地
4. 可微调

- 当然也有短板
1. 性能问题，最无法忽视。大多数情况下，本地的机器不如服务器的机器好，这是其一。其二开源的大模型几乎都是老模型，前沿模型大都是闭源的
2. 成本问题，本地机器本身不免费，如果不常用还不如直接用api。除了专业场景本地电脑要用来运行桌面环境、软件否，而不是大模型

> 所以没有最好，只有最合适

- 总结下来云端和本地的使用场景以及原因
    - 云端  
    优势：性能、效率。  
    使用场景：需要专业推理时，也就是大多数情况
    - 本地  
    优势：长期下来经济，隐私性，稳定，可微调。
    使用场景：大量专业简单业务处理，处理敏感内容，需要微调。  

举例来说  
```
场景1、长期总结大量短文本信息
场景2、按照某种标准通过某些信息分析因子
```
场景1就适合用本地模型，因为“短文”信息总结/提取，不需要推理。而且对于“长期、大量”这个来说硬件成本能被摊薄  
场景2适合API，“因子”，是通过“标准”和“信息”分析出来的，这种长线分析大多数情况下小模型搞不定  

## 基础python调用ollama闭环数据流
请求：  
```python
reply = ollama.chat(
    model="qwen2.5:0.5b",  # 使用与练习不同的小模型标签，避免把 demo 当成练习答案。
    messages=[
        {"role": "user", "content": "用一句话解释为什么雨后会有彩虹。"},  # 这是发送给本地模型的用户消息。
    ],
)
```
数据流：  
```
1、python脚本组装请求内容
2、ollama库发送http请求到ollama本地服务
3、ollama服务按照请求运行模型
4、模型把结果给ollama服务
5、ollama库取回结果到脚本
```
- 重点说一下ollama在这其中的作用。它就相当于是个传话筒，
python脚本或者终端无法直接运行大模型，需要一个中间的传话筒把不同形式的请求（比如终端或者脚本），包装好发给大模型，然后取回大模型输出再传回
它不是大模型本身
- 这是ollama用途的一部分，它同时还是本地大模型的管理工具  
常用命令及其作用：
```
# 启动ollama服务
ollama serve
# 安装模型到本地，类似于 uv add
ollama pull <model id>
# 终端运行大模型对话
ollama run <model id>
```

ollama run 是终端交互，实际使用还是多通过python脚本调用服务

## 故障排查
- 其实可以按照“基础python调用ollama闭环数据流”来逐层排查
1. 脚本编写是否正确
2. ollama库是否运行正常
3. ollama服务是否运行正常
4. 脚本指定模型是是否存在/损坏
