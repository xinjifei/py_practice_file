# 第 80 天验收标准

## 体系定位 

- 所处阶段：阶段四「AI 核心技术」的“本地模型部署 + API 调用”起点；这一小节把模型从只能使用云端服务，变成可按成本、隐私与可用性选择的基础设施。
- 今天的角色：建立本地模型调用的最小闭环——本机运行时、已下载的模型和调用客户端各司其职。后续第 81 天切换兼容 API、第 82 天做云端失败自动降级，都以这个闭环为前提。
- 目标关系：这是技术判断力（什么时候该选本地而不是云端）和 AI 协作能力（能把“调用模型”拆成可排查的组件）的基础。

## AI 分界线

- **归你（必须长在脑子里）**：本地模型不是“另一个聊天网页”，而是“模型文件 + 本机运行服务 + 客户端调用”的组合；能按隐私、网络、成本、硬件与效果做本地/云端取舍，并能区分模型没下载、服务没启动、Python 客户端调用失败这三类问题。
- **可外包（概念要知道、实现交给 AI）**：各系统的安装命令、具体模型标签、显存/内存估算、SDK 参数的逐字拼写；让 AI 按你的电脑和目标推荐、生成后仍需用上述组件边界检查它。

## 硬线（不过不能结束，达标看 note.md 写没写到位）

- [ ] 能用自己的话说明 Ollama 在本地模型链路中的位置，以及 `pull`、`run`、Python 客户端分别解决什么；能画出或写出“模型文件 → 本机服务 → 程序请求 → 回复”的数据流。
- [ ] 能根据场景在本地与云端模型间做判断：至少说清一个应选本地的场景、一个应选云端的场景，并说明“本地”带来的隐私、成本、离线能力与模型效果/硬件代价之间的取舍。
- [ ] 面对“Python 调不通本地模型”，能按组件边界提出排查顺序：模型是否已下载、Ollama 服务是否可用、模型标签是否一致、客户端/请求是否正确；理解这正是后续兼容 API 与降级策略的地基。
