# d78 研报知识库

> 在昨天的检索链路上接入 LLM，实现从「找到材料」到「依据材料回答」。

## RAG 四步流程

1. **问题 Embedding**
   - 输入：Query → 输出：语义向量
   - 作用：用于匹配知识库。（d77、m24）
2. **向量检索 Top-K**
   - 输入：Query 向量 + 向量库 → 输出：chunk + metadata
   - 作用：寻找答案证据。（d76、d77、m27）
3. **拼接 Prompt**
   - 输入：Query + chunk + metadata + 规则
   - 输出：完整 Prompt，让模型看到证据。
4. **LLM 生成**
   - 输入：Prompt → 输出：答案 + 引用
   - 作用：依据证据组织回答。

## 故障归因

- **答案自信但与文档无关**：先查 Top-K，再查 Prompt 是否遗漏，最后检查模型是否忽略证据。
- **答案正确但引用错误**：优先检查引用映射，来源应由 metadata 确定，而非模型编造。
- **文档有答案却说不知道**：检查问题措辞、Top-K、chunk 边界，再检查 Prompt 和生成规则。

## RAG 的本质与边界

> RAG 就是回答前先翻小抄。模型权重不变，变化的是输入上下文。

- **能解决**：新信息、私有数据、来源追溯。
- **不能解决**：模型推理能力、判断力、原文错误。
- **无需 RAG**：解释双资产组合方差公式，属于已有知识的数学推导。

## 引用验证

1. 检索保存 `source、chunk_index、页码`。
2. 模型输出引用编号，程序通过 metadata 映射来源。
3. 回查原文，确认引用内容确实支持结论。

**引用真实存在 ≠ 引用能支持答案。**

## 有无 RAG 对比（已实测）

**问题**：「春风动力 2026 年前三季度营收和归母净利润是多少？」

- **无 RAG**：模型以「截至 2026 年 5 月 7 日」为前提，认为前三季度尚未结束，无法提供数据。
- **有 RAG**：准确回答营收 **209.42 亿元**、归母净利润 **20.21 亿元**，均引用 `[1]`。
- **引用核对**：代码将 `[1]` 映射到 `r01_春风动力#000`，第 1 页；原文确实包含这两个数字。
- **差异归因**：不是模型变聪明了，而是有 RAG 时看到了 2026 年 10 月 21 日研报中的具体数据。
