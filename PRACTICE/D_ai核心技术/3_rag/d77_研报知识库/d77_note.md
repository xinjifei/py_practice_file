# d77 研报知识库
> 跑通最简RAG检索链路
## 节点解析
1. 数据
	- 输入：原始素材（PDF、网页、txt、图片OCR文本、财报等）
	- 输出：原始未经处理的文本素材
	- 出问题了在：现象：文档本身扫描模糊、缺页、乱码、内容残缺。优先怀疑原始数据源，理由：源头就没有目标信息，后续所有环节都救不回来。
    - 串联：无，纯技术

2. 清洗
	- 输入：原始素材文本
	- 输出：干净、无冗余噪声的纯文本（去掉页眉页脚、广告、换行、重复水印、乱码）
	- 出问题了在：现象：知识库有原文，但关键信息消失。优先怀疑【清洗】，理由：清洗规则误删了核心段落；现象：召回结果一堆乱码无意义字符，优先清洗，脏文本没过滤。
    - 串联：无，纯技术

3. 分块（Chunk）
	- 输入：清洗后的完整长文本
	- 输出：一段段边界可控、带overlap的文本chunk
	- 出问题了在：现象：一份文档只切出1块。优先怀疑【分块】，理由：分割阈值太大、分隔符不匹配没有触发切割；现象：答案刚好卡在两块chunk中间，检索不到，优先怀疑【分块】，理由：切分边界切断了完整语义，overlap不足。
    - 串联：d76 chunking策略
    > 这里概念理解不到位。我原先以为递归分块只负责越拆越碎，不知道拆完还有拼起来凑长度的环节，还以为 overlap 是通用配置，其实大多只在硬切的时候用。

4. 向量化（Embedding）
	- 输入：单条chunk文本 / 用户查询query文本
	- 输出：固定维度的语义向量
	- 出问题了在：现象：多个完全不一样的问题，召回完全相同chunk。优先怀疑【向量化】，理由：embedding模型区分度差，不同语义算出近似向量；现象：语义相近的内容向量距离很远，优先怀疑embedding，模型语义对齐失效。
    - 串联：d67 embedding是什么；m24 向量

5. 存储（向量库Collection）
	- 输入：chunk向量 + 原文 + metadata
	- 输出：入库保存的向量集合，带id、元数据、原始文本
	- 出问题了在：现象：明明跑过分块向量化，检索时完全查不到这份文档。优先怀疑【存储】，理由：写入失败、入库报错、存到别的collection；现象：按元数据过滤无效，优先存储，metadata写入出错。
    - 串联：d75 d75_chromadb基础

6. 检索
	- 输入：query向量 + 向量库
	- 输出：Top-K相似度最高的chunk列表
	- 出问题了在：现象：召回大量无关内容、相似度排序颠倒。优先怀疑【检索】，理由：相似度算法选错、召回数量设置不合理、过滤条件写错；现象：有答案但是检索不到，排除前面环节后，怀疑query本身措辞和原文表达方式差异大。
    - 串联：m27向量点积于余弦相似度；m24 向量

## 检索质量判定与归因
> 如何判断检索质量、如何修复
- 核心思路：人工选定正确答案，进行测试，观察结果。
- 方法：人工标注，自动化脚本重复跑判据。这里的标注的目标必须要是chunk，不能留一点余地，这样的脚本输出才能当作最终判据
- 标准：最好的情况top-1就是正确答案，但是最低标准是整个top-3中存在标注的正确答案。
- 迭代归因：如果测试脚本跑出来的结果与“标准”相差甚远，就使用“节点解析”中的“出问题了在”中的思路进行排查修改
