- 和目标的关系：AI 协作能力。昨天学的是「定义角色」，今天学的是「**定义产出**」——让 AI 吐出来的东西能被程序接住。判断力落点是：拿到一个模糊需求，能不能判断该用哪招——要不要给例子？要不要 CoT？要不要结构化？

## AI 分界线
- **归你（必须长在脑子里）**：
  - Few-shot 的本质——例子不是用来「教模型事实知识」的，是用来「**用具体样本示范这类输入该怎么处理**」的。示范的既可以是**输出格式**（JSON 字段、结构），也可以是**处理模式**（d72 要让 AI 模仿的就是"策略思路"这种模式）。模型从例子里学的是"你要什么样的输出"，不是"这件事的答案"
  - 0-shot / few-shot 的选择判断：什么时候把要求说清楚就够了，什么时候必须给例子
  - CoT 为什么有效——直接接 d66 / d68：模型是**逐 token 生成**的，先写出来的中间步骤本身变成了后续生成的上下文，等于给它一块草稿纸
  - `指令 + 例子 + 格式` 三段结构，以及三段各自解决什么问题
  - 成本意识：few-shot 的例子是**每一轮都重复发送**的文字，同样占 token、占 Context Window（接 d68 / d69）
- **可外包（概念要知道、实现交给 AI）**：
  - 具体 Prompt 措辞的润色、换个更漂亮的表达
  - JSON 的 schema 怎么设计、字段怎么命名
  - CoT 那句咒语的具体写法（「让我们一步步思考」的各种变体）
  - API 调用代码本身
