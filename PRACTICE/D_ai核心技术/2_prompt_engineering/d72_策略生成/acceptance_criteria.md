# 第 72 天验收标准

## 体系定位
- 所处阶段：阶段四「AI 核心技术」› Prompt Engineering 在量化场景中的应用，第 3/4 天（同 section，**不跨组**）。
- 前面铺了什么：d70 给了 `指令 + 例子 + 格式` 三段结构（Few-shot 用例子划**输出格式**）；d71 处理了「输出不可靠」，把校验和兜底补上。这两天的 Few-shot 都在示范**形状**——JSON 的字段长什么样。
- 今天的概念：Few-shot 换了个用法——例子示范的不是输出格式，而是**策略的结构**（信号 → 过滤 → 仓位 → 出场）。AI 学到的是**骨架**，往里填的是新零件。同时今天第一次出现真正的量化判断题：**前视偏差**——AI 生成的策略可能逻辑漂亮、代码能跑、回测赚钱，但它偷看了未来。
- 和目标的关系：**技术判断力**（今天的主场）。d70/d71 练的是"怎么让 AI 听话"，今天练的是"AI 交上来的东西怎么判断能不能用"。判断力的落点：拿到 3 个看起来都对的策略，能不能挑出哪个在骗你。
- **后续依赖**：本节内的 d73（Prompt 版本管理：对比不同版本的输出质量）对「质量」的判据就是今天的三把尺子——生成策略这类任务，没有这三把尺子，"哪个版本更好"根本无从比。d74 是本节复习日。之后进入 RAG（d75+），不再直接吃今天。
- **今天的分量提醒**：前视偏差不是"今天的一个知识点"，是后面回测/策略部分的**通用陷阱**。今天只要求你认识它、能认出它。

## AI 分界线
- **归你（必须长在脑子里）**：
  - **审查三把尺子**，尤其是**前视偏差**——这一条不能外包。AI 生成策略、AI 写回测代码，都可能带着它；它不会报错、不会崩、回测还特别好看。只有你能拦
  - Few-shot 示范「结构」和示范「格式」的区别：格式错了程序会崩，结构烂了程序照样跑——**后者靠你判断**
  - 「AI 是创意起点，不是答案」这句话的分工含义：AI 负责给出候选和变体，**筛选、改写、否掉**是你的活
  - 逻辑自洽为什么是第一把尺子：一个说不出「为什么能赚钱」的规则，即使回测好也是噪声拟合
- **可外包（概念要知道、实现交给 AI）**：
  - 策略想法的具体枚举、指标组合的花样
  - 把选定的策略翻译成 Python 函数（规则你已经定死了，代码是体力活）
  - 均线/RSI/布林带的公式本身（之前数学轨道学过，忘了让 AI 补）

## 代码练习（少量，仅当硬线涉及动手写代码）
- [ ] 练习1：用 Few-shot 让 AI 生成 **3 个策略思路**（例子用**均线交叉的规则描述**，这是教材指定的；不要用 demo 里的布林带/RSI），然后**逐条按三把尺子审查**，把每个策略"过/不过、卡在哪把尺子"记下来。最后选 1 个写成可回测的 Python 函数——函数只负责**算信号**（返回 1/0/-1 这类），不用真跑回测
- [ ] 练习2：**前视偏差实验**（今天最重要的一次动手）——同一个策略写两版信号：一版故意偷看未来（最日常的形式：**漏掉 `shift(1)`**，让当日信号当日成交；露骨的形式：`shift(-1)` 把明天的涨跌搬来今天），一版只用当下和过去的数据（信号 delay 一天才生效）。拿同一段行情跑，对比两版的累计收益。**目的不是看数字大小，是亲眼看到"偷看未来"能把一个烂策略变成神仙策略**。数据自选（akshare 拉一段日线，或自己造一段），**不要用 demo 里的合成数据**
