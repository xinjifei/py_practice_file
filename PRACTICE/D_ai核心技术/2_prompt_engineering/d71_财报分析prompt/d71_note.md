# d71 提取json
> 用大模型提取文章中的关键信息为json
## 原则
> 总原则
1. 应该默认模型的输出是有结构性问题的，模型底层的每一次解码都是一次存在不确定性的输出，不能把希望寄托在它输出的的内容直接就能干净可用。一定要在后期加防护（具体底层原理参考*d68_note.md*）
2. 在prompt设计时要尽可能的钉死，不要留余地

## 方法
> 遵守总原则的方法
1. 后期防护
    - 在本地需要有纯机器的验证结构是否完整，语义上是否符合预期（层3）
    - 请求服务时需要要求返回json格式（层2）
2. prompt（层一）
    - 显式定义字段，不能扔一个字段名称内容考模型猜测。特别是有时候对数据类型有要求；比如让他总结一个收益率有可能有很多种情况 20——int 0.2——float 还有跟离谱的 "20"——str，这三种情况如果放到真实程序里面前两个情况大都不会影响到后续计算，但是会输出一个压根没有意义的数字，最后一种情况就是程序直接崩
    - 使用few-shot法进行输出举例

## 三个层面的失效方式
1. 模型概率原因理论上有可能什么都无法确定，只能保证会输出字符串
2. 只能确定输出 “是json”，但是其中还有变量：是什么，它无法保证
3. 最终的排查，只要是程序写对了本身不会有漏网之鱼，但是它会错在重试这个问题上面，如果只是干重试就是抽卡，需要带出来问题才能改
## 问题排查：
> 有问题时的排查思路
```
if 输出 == json:
    层二没有问题
    层一有问题，比如没有定义清楚类型，字段不齐全对不上下游程序
else:
    层二没有守好，输出的内容甚至无法解析，层一也有可能没说清楚
```
